# Turtle.Life

## Открытие и проверка проекта

Проект подготовлен из штатного пустого 3D-шаблона Unity с Universal Render Pipeline (URP). Версия редактора — **6000.5.6f1**. Игровая логика пока отсутствует.

1. Открыть Unity Hub и активировать доступную лицензию в настройках лицензий, если редактор просит активацию.
2. В разделе Projects выбрать Add / Add project from disk и указать папку `Turtle.Life`, содержащую `Assets`, `Packages` и `ProjectSettings`.
3. Открыть проект редактором `6000.5.6f1`. При первом запуске дождаться загрузки пакетов и импорта ассетов; может потребоваться интернет.
4. Открыть `Assets/Scenes/SampleScene.unity` и нажать Play. Это пустая стартовая сцена с камерой, освещением и настройками окружения.
5. Проверить вкладку Console: после импорта и запуска не должно быть красных ошибок. Повторным нажатием Play остановить сцену.

Для проверки отдельной сборки открыть File → Build Profiles, выбрать Windows, убедиться, что `SampleScene` включена в список сцен, и выполнить Build and Run в папку `Builds/Windows`. Для сборки нужен установленный модуль поддержки выбранной платформы.

### Отслеживание изменений

В Git сохраняются `Assets` вместе со всеми `.meta`, `Packages`, `ProjectSettings` и документация. Включены текстовая сериализация и видимые `.meta`-файлы. Кэши, локальные настройки и сборки исключены через `.gitignore`.

После работы сохранить сцену и ассеты в Unity, затем проверить изменения через Git в Rider или команды `git status` и `git diff`. Перемещать и переименовывать ассеты лучше через окно Project в Unity, чтобы сохранить связи через `.meta`. Изменения в Play Mode обычно не сохраняются после его остановки.

Версии пакетов в `Packages/manifest.json` согласованы с метаданными установленного редактора `6000.5.6f1`; разрешённые зависимости фиксируются в `Packages/packages-lock.json`. При смене версии Unity нужно проверять совместимость пакетов: исходный шаблон содержал устаревшие версии, вызывавшие ошибки компиляции.

Кооперативная 3D-игра о черепашках, которые пытаются выбраться из аквариума. Игроки исследуют окружение, передвигают предметы и помогают друг другу преодолеть препятствия.

## Рабочие предположения

- Платформа первого выпуска — ПК, управление клавиатурой и мышью.
- Онлайн-кооператив для 2–4 игроков с приватной комнатой и одним игроком-хостом.
- Одна сессия длится примерно 15–25 минут.
- Первая версия содержит один аквариум и один маршрут побега.
- Одиночный режим, публичный подбор игроков и другие платформы — за пределами первой версии.

Эти ограничения нужны, чтобы сначала проверить, интересно ли совместно решать задачи и управлять черепашками.

## Игровой цикл

1. Осмотреть аквариум и заметить возможный путь к выходу.
2. Найти полезные предметы: камни, ветки, декорации и плавающие платформы.
3. Вместе изменить окружение и открыть следующий участок маршрута.
4. Помочь всем черепашкам пройти препятствие.
5. Достичь края аквариума и выбраться всей командой.

Победа засчитывается, когда все игроки достигли безопасной зоны. Падение возвращает черепашку к последней общей контрольной точке, чтобы ошибка одного игрока не заставляла всю команду начинать заново.

## Механики первой версии

- **Перемещение:** ходьба по дну и суше, плавание с управлением глубиной, небольшой подъём на уступы.
- **Взаимодействие:** толкание предметов и активация рычагов или кнопок.
- **Совместные действия:** тяжёлый предмет двигается только усилиями нескольких черепашек; один игрок удерживает механизм, пока остальные проходят.
- **Помощь товарищу:** возможность подтолкнуть или поднять отставшего игрока в заранее предусмотренных местах.
- **Общение:** простая отметка точки интереса; голосовая связь на первом этапе остаётся во внешнем приложении.

Для старта достаточно двух видов совместных задач. Строительство башен из черепашек, свободное хватание любых объектов и сложную физику панцирей стоит проверять отдельными экспериментами: они могут сильно увеличить сложность управления и сетевой синхронизации.

## Пример первого уровня

| Участок | Задача команды | Чему учит |
| --- | --- | --- |
| Дно аквариума | Вместе сдвинуть декорацию, закрывающую проход | Совместному толканию |
| Подводный тоннель | Удержать створку, чтобы товарищи добрались до фиксатора | Распределению ролей |
| Островок | Переместить опору и подняться на уступ | Работе с окружением |
| Край аквариума | Открыть общий выход и собрать всех в безопасной зоне | Завершению побега всей командой |

Каждую задачу нужно проектировать так, чтобы её могли решить двое. Для трёх и четырёх игроков можно добавлять роли и ускорять выполнение, не требуя обязательного присутствия четырёх участников. Перед закрывающимися проходами нужны фиксаторы или обходные пути, чтобы последний игрок тоже мог пройти.

## План разработки

### 1. Зафиксировать правила и границы проекта

- Описать управление, условия победы, возврат после падения и правила контрольных точек.
- Нарисовать схему аквариума и последовательность из трёх совместных задач.
- Определить визуальное направление: игрушечный аквариум с читаемыми формами и выразительными черепашками.
- Создать Unity-проект с 3D-рендерингом, настроить Git и правила хранения ассетов.

**Готово, когда:** есть короткое описание игры, схема уровня и пустая запускаемая сцена проекта.

### 2. Сделать прототип управления

- Собрать аквариум из примитивов без финальной графики.
- Добавить одну черепашку, камеру, ходьбу, плавание и переход между водой и сушей.
- Проверить коллизии, подъём на небольшие уступы и восстановление после застревания.
- Сделать управление предсказуемым; комичность получать из анимации и реакций, не из постоянной потери контроля.

**Готово, когда:** игрок без объяснений проходит небольшой маршрут по дну, воде и островку, а камера не мешает ориентироваться.

### 3. Рано проверить сетевой фундамент

- Выбрать сетевой стек после проверки его поддержки нужных платформ, физики и способа подключения.
- Сделать создание комнаты, подключение по коду и появление отдельных черепашек.
- Передавать движение, взаимодействия и состояние общих предметов через хост.
- Проверять на хосте допустимость действий: расстояние до предмета, доступность механизма и выполнение условий задачи.
- Сразу испытать управление и одно совместное действие в двух отдельных сборках.
- Определить поведение при выходе участника: освободить удерживаемый механизм, пересчитать требования задачи, сохранить возможность закончить уровень оставшейся командой из двух и более игроков.
- Для первой версии при выходе хоста завершать сессию с понятным сообщением; перенос хоста отложить.

**Готово, когда:** два игрока подключаются, видят друг друга и совместно двигают один предмет без расхождения его итогового положения.

### 4. Собрать первый полноценный кооперативный фрагмент

- Реализовать тяжёлую декорацию, створку с фиксатором и общую контрольную точку.
- Добавить подсказки взаимодействия и понятную обратную связь: кто держит механизм и сколько помощников требуется.
- Провести тест с двумя людьми без устных инструкций разработчика.
- Убрать ситуации, где один игрок выполняет всю задачу, а второй долго ждёт.

**Готово, когда:** небольшой фрагмент длительностью 5–10 минут требует участия обоих игроков и проходится без помощи автора.

### 5. Собрать весь маршрут побега

- Соединить три задачи в один аквариум с началом, контрольными точками и выходом.
- Добавить помощь отставшим и восстановление предметов, которые оказались недоступны.
- Сделать экран победы и повторный запуск сессии.
- Проверить прохождение составом из двух, трёх и четырёх игроков.

**Готово, когда:** команда может пройти весь путь от создания комнаты до победы без тупиков и ручного исправления сцены.

### 6. Добавить визуальный стиль и звук

- Заменить примитивы моделями черепашек и декорациями аквариума.
- Добавить анимации ходьбы, плавания, усилия и помощи товарищу.
- Настроить воду, освещение и эффекты так, чтобы путь и интерактивные объекты оставались хорошо видны.
- Добавить звуки действий, окружения, контрольных точек и победы.
- Дать игрокам разные цвета или элементы панциря для узнаваемости.

**Готово, когда:** игроки различают персонажей, понимают результат действий и уверенно читают окружение.

### 7. Подготовить тестовую сборку

- Добавить главное меню, настройки звука и чувствительности, паузу и выход из комнаты.
- Проверить подключение через интернет, задержку, потерю соединения и выход хоста.
- Проверить частоту кадров на выбранном минимальном ПК и ограничить число активных физических объектов.
- Провести несколько внешних игровых тестов, записать непонятные места, застревания и длительные ожидания.
- Исправить блокирующие ошибки и подготовить инструкцию запуска для тестировщиков.

**Готово, когда:** новая команда самостоятельно создаёт комнату, проходит уровень и запускает следующую сессию.

## Технические ориентиры

- Разделить управление персонажем, взаимодействия, правила головоломок, сетевую передачу состояния и интерфейс.
- Общие предметы и прогресс задач должны иметь один источник истины — хост. Клиенты отправляют намерения действий.
- Для движения сначала использовать простой управляемый контроллер. Полностью физического персонажа вводить только после проверки, что это улучшает игру.
- Избегать головоломок, требующих точного совпадения физических объектов на разных компьютерах. В важных местах использовать заданные положения, фиксаторы и явные состояния механизмов.
- Начать с одного типа взаимодействия и расширять систему по мере появления реальных задач.
- Версии Unity и пакетов зафиксировать в проекте после выбора. Конкретные сетевые пакеты и сервис подключения выбрать на этапе сетевого прототипа.
- Для Unity настроить текстовую сериализацию и видимые `.meta`-файлы; хранить `Assets`, `Packages`, `ProjectSettings` и `.meta` в Git. До первого коммита проекта дополнить `.gitignore` исключениями для `Library`, `Temp`, `Logs`, сборок и других генерируемых файлов Unity.

## Основные риски

| Риск | Как проверить и уменьшить |
| --- | --- |
| Управлять черепашкой неудобно | Проверить движение и камеру до создания финальной графики |
| Сетевая физика расходится | Рано испытать общий предмет в двух сборках; ограничить свободную физику |
| Один игрок делает всё | Строить задачи вокруг разных одновременных ролей и проверять это на игровых тестах |
| Команда застревает после ошибки или отключения | Добавить сброс предметов, контрольные точки и освобождение механизмов |
| Объём проекта постоянно растёт | Довести один аквариум до завершённой сессии перед новыми уровнями |

## Что отложить до проверки первой версии

- Несколько аквариумов и процедурную генерацию.
- Публичный подбор игроков, перенос хоста и подключение в середине прохождения.
- Сложную симуляцию воды, разрушения и свободное строительство.
- Развитие персонажей, магазин косметики и сюжетную кампанию.
- Собственный голосовой чат и кроссплатформенную игру.

## Ближайший шаг

Создать сцену из простых форм: аквариум, дно, вода, островок и черепашка. Сначала добиться приятного перемещения и понятной камеры. Затем подключить второго игрока и проверить одну задачу — совместное перемещение тяжёлой декорации.
